Ground truth: official BOREAS Objects-V1 timestamped 3D tracking labels; UUID, class, dimensions, location, yaw/orientation, and point-count fields are read via the unmodified official pyboreas BoundingBoxes parser.
Coordinate chain: p_enu(label time) = T_enu_lidar(label time) @ p_lidar; T_enu_radar(t) = T_enu_lidar(t) @ inverse(T_radar_lidar); p_radar(t) = inverse(T_enu_radar(t)) @ p_enu(t). Object centers are linearly interpolated in ENU between adjacent same-UUID tracking labels only; no extrapolation is performed, and interpolation requires the UUID to be present in both adjacent label frames. The box extent is transformed using the official label box corners, with label-time orientation held fixed and its center translated by interpolated GT motion.
Radar candidate range and azimuth are the actual extracted peak's bin-center range and per-azimuth value/time from the official Radar loader. Objects are within Radar FOV when their radial box extent overlaps [minimum detectable range, maximum scan range]; the rotating BOREAS Radar is treated as 360-degree.
Association requires BOTH candidate-center range error <= the projected 3D box range radius + configured range padding, AND wrapped azimuth error <= the box angular half-extent + configured angular padding. Candidate assignment is one-to-one per label frame, prioritizing normalized polar error then intensity and stable identifiers.
CSV timestamp_delta_ms is absolute camera-to-Radar filename timestamp difference; label_radar_timestamp_delta_ms is the label-to-Radar difference used for scan selection. Both are reported separately.
Associated CSV rows preserve expected and candidate polar coordinates, range/azimuth errors, associated_radar_count, and the extracted candidate's deterministic zero-based index in that Radar scan's ordered candidate list. The index is scan-local, not a persistent Radar object identity. association_distance_px is blank because this geometric polar validator does not compute image-pixel distance.
These are geometric consistency associations against object ground truth, not Radar detection ground truth. No Radar precision/recall or verified Radar-to-ByteTrack identity is claimed.

Association status meanings:
  ASSOCIATED: an extracted Radar intensity candidate met both polar gates.
  NO_RADAR_ASSOCIATION: object lies in Radar FOV, but no candidate met both gates.
  OUT_OF_RADAR_FOV: the 3D object extent lies outside the scan's radial coverage.
  TIMESTAMP_MISMATCH: no Radar scan falls within the configured label-time gate.
  INVALID_GEOMETRY: required GT trajectory or timestamped sensor pose was unavailable/non-finite.

Interpretation: successful geometric overlap is not independent Radar object detection truth. Radar-track association remains INCONCLUSIVE until an independent Radar detection/identity reference is available.
